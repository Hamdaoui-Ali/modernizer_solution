## 1. Project Overview

### What It Does
The **AI Migration Control Tower** is a governed, human-in-the-loop migration platform for Java/Spring Boot applications. It orchestrates three-stage pipeline migrations (Java 11 → 17 → 21, Spring Boot 2.7 → 3.5.6) with human approval gates, plan amendments, repair proposals, patch validation, and deterministic proof reports.

## 5. What the Backend Accepts as Input

### Common Rules for All Routes

- **Host header:** Must match `127.0.0.1:8000`
- **Mutation requests (POST/PUT/PATCH/DELETE):**
  - `Origin: http://127.0.0.1:3000` required
  - `X-Control-Tower-Client: control-tower-frontend` required
  - `Content-Type: application/json` required
  - Extra fields in request body are **rejected** (StrictModel)
- **All responses:** `X-Correlation-ID` header; data is redacted (paths, secrets, env vars removed)
- **Pydantic validation failures:** Return 422 with `{"error":{"code":"INVALID_REQUEST",...}}`
- **Unexpected exceptions:** Return 500 with `{"error":{"code":"INTERNAL_SERVER_ERROR",...}}`

### POST /v1/jobs (Create Diagnostic Job)
- **Purpose:** Create a new migration/diagnostic job
- **Required header:** `Idempotency-Key`
- **Request body (`CreateJobRequest`):**
  ```json
  {
    "runner_profile_id": "runner-default",
    "runner_profile_version": "2026.06",
    "pipeline_id": "springboot-216-to-356-java21-three-stage",
    "pipeline_version": "2026.06",
    "legacy_source_root_id": "source-root",
    "legacy_source_relative_path": "src",
    "output_root_id": "output-root",
    "output_relative_path": "out",
    "target_proof_level": "ANALYZED",
    "enabled_gates": [],
    "policy": {
      "continue_after_warning": false,
      "enable_runtime_gate": false,
      "enable_endpoint_gate": false
    }
  }
  ```
- **Validation rules:**
  - All string fields required (NonEmptyString)
  - `target_proof_level`: Must be valid `TargetProofLevel` (enum values: `ANALYZED`, `BUILD_TEST_VERIFIED`, `PROVEN`)
  - `enabled_gates`: Tuple of non-empty strings
  - `policy.continue_after_warning`: boolean (default false)
  - `policy.enable_runtime_gate`: boolean (default false)
  - `policy.enable_endpoint_gate`: boolean (default false)
- **Response (201):** `{"job":{"job_id":"...","version":1,"state":"created",...},"etag":"\"job-...-v1\""}`
- **Error (400):** Missing `Idempotency-Key` → `{"error":{"code":"IDEMPOTENCY_KEY_REQUIRED",...}}`
- **Error (422):** Missing required field → `{"error":{"code":"INVALID_REQUEST",...}}`
- **Error (409):** Duplicate idempotency key → `{"error":{"code":"IDEMPOTENCY_CONFLICT",...}}`

### Example curl:
```bash
curl -s -X POST http://127.0.0.1:8000/v1/jobs \
  -H "Content-Type: application/json" \
  -H "Origin: http://127.0.0.1:3000" \
  -H "X-Control-Tower-Client: control-tower-frontend" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"runner_profile_id":"runner-default","runner_profile_version":"2026.06","pipeline_id":"springboot-216-to-356-java21-three-stage","pipeline_version":"2026.06","legacy_source_root_id":"source-root","legacy_source_relative_path":"src","output_root_id":"output-root","output_relative_path":"out"}'
```

### Hard Boundaries Confirmed

| Constraint | Enforced By |
|---|---|
| Boot 4 not selectable | Pipeline definition schema, dropdown population |
| Boot 3.5.14 not execution-relevant | Pipeline definition (targets are 2.7.18 and 3.5.6) |
| Browser cannot choose raw paths | Filesystem root dropdowns only; relative paths are validated strings |
| Browser cannot choose Maven goals | Backend validates to `^(compile\|test-compile)$` only |
| Browser cannot choose shell commands | No shell input anywhere in UI or API |
| Browser cannot choose working directories | Derived from root + relative path |
| Browser cannot choose model deployments | Model profiles registered server-side; only profile_id selectable |
| LLM cannot execute | No execution endpoints for LLM; model invocations are audit-only |
| LLM cannot approve | Approvals require checksum-guarded POST with human actor |
| LLM cannot write files directly | File writes are typed privileged actions requiring approval |
| LLM cannot create proof | Proof gates are deterministically computed from stage chain ledger |
| Public outputs redacted | All API responses pass through `redact_public_data` |
| No secrets/env/local paths in responses | Regex-based redaction: paths, env assignments, secret key names, PIDs |
| Shell disabled by default | No shell tool exposed; Maven/write are typed privileged actions |
| Maven/write are typed privileged actions | Must pass validation → approval → execution pipeline |

### Redaction Coverage (`security.py`)

- Windows absolute paths: `C:\...` → `[redacted-path]`
- POSIX absolute paths: `/home/...` → `[redacted-path]` (except valid http/https URLs)
- Environment variable assignments: `VAR=value` → `[redacted-env]`
- Secret key names: `secret`, `token`, `password`, `credential`, `api_key` → `redacted`
- PIDs: `pid`, `process_id`, `handle` keys → `[redacted]`
- Traceback strings → `Internal server error.`

## 9. Troubleshooting

### Backend Cannot Start

| Symptom | Check |
|---|---|
| `ModuleNotFoundError: migration_factory` | Run from repo root; `pip install -e ".[test]"` |
| Port 8000 in use | `lsof -i :8000` / `ss -tlnp \| grep 8000` |
| `CONTROLLER_OWNERSHIP` error | Lock file exists in `/tmp/control-tower-*.lock`; delete stale lock |
| DB locked | Wait for SQLite timeout (5s); kill competing process |
| Migration checksum mismatch | Delete DB and let it re-initialize |

### Frontend Cannot Reach Backend

| Symptom | Fix |
|---|---|
| CORS errors in browser | Backend must respond to `Origin: http://127.0.0.1:3000` |
| `INVALID_ORIGIN` | Use `http://127.0.0.1:3000`, not `localhost:3000` |
| `UNTRUSTED_HOST` | Use `127.0.0.1:8000`, not `localhost:8000` |
| Network errors | Verify backend is running; check firewall |

### DB / Migration Problems

- Delete the SQLite DB: `rm .control-tower-dev/control_tower.sqlite3` (dev) or `rm ~/.local/state/ai-migration-control-tower/control_tower.sqlite3` (production path)
- Restart backend to auto-recreate and apply all 27 migrations

### Missing Runtime Directory

- `dev_app.py` auto-creates `.control-tower-dev/{source,output,workspace}/` on first start
- If running without `dev_app.py`, ensure filesystem roots exist at configured paths

### npm Install / Test / Build Problems

- `rm -rf node_modules && npm install` for clean install
- Check Node version: `node --version` (needs ≥18)
- `npm run typecheck` for TypeScript errors
- `npm test` for vitest tests (should get 107/107)

### pytest Timeout

- Full 1,224-test suite may time out on low-resource machines
- Run individual test files instead:
  ```bash
  python -m pytest tests/control_tower/test_fastapi_diagnostic_queue.py -v
  ```
- Use `-x` to stop on first failure

### API 404 / 400 / 422 Cases

| Status | Meaning | Fix |
|---|---|---|
| 404 | Resource not found | Check job_id, command_id, etc. |
| 400 | Bad request | Check Idempotency-Key, required fields |
| 409 | Conflict | Duplicate idempotency key, stale version |
| 412 | Precondition failed | Include correct `If-Match` ETag |
| 422 | Validation error | Check request body against contract |
| 428 | Precondition required | Include `If-Match` header |
| 429 | Rate limit | Too many SSE clients (max 8) |
| 501 | Not implemented | Worker launcher not configured |
| 503 | Service unavailable | Singleton ownership unavailable |

## V2 Addendum — Local Migration Cockpit

****Status:** Implemented and wired (P0 fixes complete)
**Integration Branch:** `V2IMPROVMENT`  
**PR Target:** `V2IMPROVMENT` (never `DEMO2`)

### V2 Architecture Changes

V2 turns the Control Tower from a diagnostic job UI into a local migration cockpit.

All V2 services (A1-A13) are now implemented, persisted to SQLite, and exposed via REST API endpoints.

Key changes:

1. **New Migration Setup** (`/migrations/new`): Paste PowerShell env block or enter typed fields. Backend parses allowlisted keys only. Azure secrets are blocked.

2. **Settings UI** (`/v1/settings/ai`): Redacted Azure Foundry settings with env refs only. Never returns endpoint URLs, API keys, or deployment IDs.

3. **Setup Persistence** (`POST /v1/migration-setups`): Append-only setup drafts with SHA-256 checksum gating.

4. **Preflight** (`POST /v1/migration-setups/preflight`): Deterministic readiness checks. Azure status is non-blocking.

5. **Job Creation** (`POST /v1/v2/migration-jobs`): Persists parent job from ready setup with three fixed-stage chain.

6. **Stage 1 Start** (`POST /v1/v2/migration-jobs/start-stage1`): Backend-owned command manifest. Persisted to `v2_stage_commands`. Browser cannot supply argv/env.

7. **Stage Auto-Progression** (`POST /v1/v2/jobs/{job_id}/stages/progress`): Stage 2 from Stage 1 sandbox, Stage 3 from Stage 2 sandbox. No manual stage buttons.

8. **Approval Mapping** (`POST /v1/v2/jobs/{job_id}/approvals/{card_id}/approve|reject`): Durable decision cards with checksum gating. LLM cannot approve.

9. **Assistant** (`POST/GET /v1/v2/jobs/{job_id}/assistant/messages`, `POST .../actions/draft`): Read-only guidance. Drafts instructions and pending actions. Cannot execute/approve/write/change route.

10. **Repair Flow** (`POST /v1/v2/commands/{cmd}/repair/flow-proposal`, `POST .../proposal/{id}/approve`): Failed command evidence → bounded repair proposal → approval → sandbox patch.

11. **Cockpit** (`/migrations/[jobId]`): Stage timeline, evidence, decisions, assistant, proof panels. No execution controls.

12. **Schema Validation**: `SchemaValidator` class validates model output against strict JSON schemas at runtime. Covers PlanProposal, RepairProposal, ReviewerCritique, ActionRequest, AssistantAnswer.

### V2 Setup Flow

```text
User pastes env block → POST /v1/migration-setups/parse-env
                      → fields auto-filled in form
User saves → POST /v1/migration-setups
User runs preflight → POST /v1/migration-setups/preflight
User checks readiness → GET /v1/migration-setups/{id}/readiness
User creates job → POST /v1/v2/migration-jobs
User starts Stage 1 → POST /v1/v2/migration-jobs/start-stage1
Backend auto-progresses → Stage 2, Stage 3
```

### V2 Security Rules

- No `NEXT_PUBLIC_*` Azure secrets
- No endpoint URLs, API keys, or deployment IDs in API responses
- Azure health never blocks deterministic migration start
- Browser cannot supply argv, env, Maven goals, or model deployments
- Assistant cannot execute, approve, write, change route, or override proof
- Worker executes backend-owned manifests only
- Approval requires exact checksum match
- All setup/preflight tables are append-only

### Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| 403 on POST | Missing mutation headers | Add Origin, X-Control-Tower-Client |
| 422 on POST | Pydantic model inside app | Move model class to module level |
| "cannot commit - no transaction" | Explicit commit in async handler | Remove explicit commit, let UoW handle it |
| 503 Service Unavailable | Controller ownership conflict | Wait or kill other process |
